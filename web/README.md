# web — 흉가 드론 관제 (HAUNTED OPS) 웹 UI

2D 평면도에서 **드론이 순찰할 구역을 지정**하면, 방문 순서를 정하고 학습된
강화학습(SAC) 정책으로 **다구간 순찰 경로**를 만들어 주는 관제 화면.
실제 비행과 카메라 화면은 Unity 시뮬레이터가 맡는다.

`playground/` 는 실험용 프로토타입 모음이고, **실제로 돌려서 쓰는 웹 앱은 이 폴더**다.
서버는 최상위 `web_server.py`.

## 실행

```bash
conda activate tello
python web_server.py            # 저장소 최상위에서. http://localhost:8000
```

정책 로드에 약 6초가 걸리고(1회), 이후 한 구간 계획은 0.05~0.5초다.
`--no-rl` 로 띄우면 정책 없이 UI 만 서빙되고, 프론트는 구간마다 방그래프
직선 경로로 폴백한다.

## 파일

| 파일 | 역할 |
|---|---|
| `HAUNTED OPS.dc.html` | 게임 셸 — 로비 / 관제 / 브리핑 / Unity 작전 / 순찰 완료 / **순찰 보고서** / 순찰 중단 / 기록 |
| `드론 관제.dc.html` | 지도 화면. `dc-import` 로 위 셸의 '관제' 단계에 삽입된다. **순찰 구역 선택 + 다구간 경로**가 여기 있다 |
| `support.js` | 시안이 쓰는 템플릿 런타임(dc-runtime). React/ReactDOM UMD 를 unpkg 에서 자동 로드하고 `<x-dc>` 템플릿을 렌더한다 — 최초 실행 시 인터넷 필요 |
| `uploads/` | `web_meta.json`(방/문/층 메타), `floor_*.png`(층별 평면도), `detections.json`(가구 인스턴스) |
| `index.html` | `HAUNTED OPS.dc.html` 로 보내는 리다이렉트 |

`uploads/` 의 평면도·메타는 `playground/demo_house/export_web_assets.py` 산출물이고,
`detections.json` 만 디자인 프로젝트에서 함께 가져왔다. 방을 다시 찍거나 점군이
바뀌어 에셋을 갱신할 땐 이 폴더로 직접 내보내면 된다:

```bash
python playground/demo_house/export_web_assets.py --out web/uploads
```

(인자 없이 실행하면 기존 `playground/demo_house/web_assets/` 로 나가고, 그건 구
프로토타입 `playground/demo_house/web_ui/` 가 쓰는 사본이다.)

## 순찰 구역 지정

순찰 요청은 `targets` 배열 + `returnHome` 하나다. **배열 순서가 곧 방문 순서**다.

- 평면도에서 **방을 클릭 = 순찰 대상 추가/해제**(다중 선택). 선택된 방은
  붉게 채워지고 순번이 붙는다.
- 층 탭 아래 **「이 층 전체 순찰」** 로 층 단위 지정. 「해제」로 그 층만 뺀다.
- 좌측 방 목록 클릭도 같은 토글이고, 우측 패널에서 순서 변경(▲)·개별 제외(✕)·
  전체 해제가 된다.

방문 순서는 드론 현재 위치에서 방그래프 홉 수 기준 **최근접 우선**으로 정한다
(`orderRooms()`).

> **자연어로 구역을 고르는 경로는 이 웹에 없다.** 별도로 돌아가는 Qwen
> (`3D-segmentation/webapp_llm/llm_parser.py`)이 맡는다. 붙일 때는 그쪽이 낸 방
> 목록을 `setTargets(ids)` 로 넘기면 순서·경로·payload 는 그대로 재사용된다.

## 다구간 순찰 경로

`POST /plan` 은 한 구간(start→goal)만 계산하므로, 프론트가
`드론 → 대상1 → 대상2 → … → (복귀)` 를 **순서대로 호출해 이어붙인다**.
각 구간의 출발점은 앞 구간 응답의 (스냅된) `goal` 을 그대로 쓴다.

```
POST /plan   {"start":[x,y,z], "goal":[x,y,z]}
     →       {"engine":"SAC · model_geo_best", "success":true, "steps":83,
              "bumps":0, "dist":0.50, "flown":27.89, "ms":537,
              "start":[...], "goal":[...],        // 실제로 쓰인(스냅된) 좌표
              "path":[[x,y,z], ...]}              // 3D 궤적
```

- 서버는 `playground/reinforce_learning/model_geo_best.zip` 정책을 **결정론**으로
  롤아웃한다. 방그래프 BFS 나 RRT* 가 아니라 정책 단독 추론이 경로를 만든다.
- 한 구간이 실패하거나 서버가 없으면 **그 구간만** 방그래프 직선으로 채우고
  나머지는 계속 계획한다(패널에 대체된 구간이 주황색으로 표시된다).
- 지도에서 순찰 구간은 **붉은 점선**, 복귀 구간은 **초록 실선**으로 그린다.
- 궤적의 층은 z 로 판정한다(`z<0.2` → 1층, `z<2.9` → 2층, 그 외 3층).

「순찰 시작」을 누르면 이 계획이 브리핑 화면(층별 평면도 3장 + 순찰 구역
하이라이트 + 방문 순서 마커)으로 넘어가고, 「작전 시작」이 Unity 화면을 연다.

## Unity 화면 보기

Unity 는 네이티브 exe 라 브라우저에 임베드할 수 없다. 그래서 `getDisplayMedia`
로 **그 창을 화면 공유**받아 `<video>` 로 그린다(`window.__simShare`, 셸과 지도가
같은 스트림을 공유). 권한창은 사용자 클릭 안에서만 뜨므로 「시뮬레이터 화면 연결」
버튼을 눌러야 한다.

**작전 화면은 항상 전면(full-bleed)이다.** 시뮬 영상이 화면을 꽉 채우고 관제
크롬(상단 바 / 하단 버튼)은 그 위에 반투명 그라데이션으로 얹힌다. 화면에 들어갈 때
브라우저 전체 화면(Fullscreen API)도 자동으로 요청한다 — `requestFullscreen` 은
"사용자 조작 직후"(Chrome 약 5초)에만 허용되는데 「작전 시작」 클릭 → 준비 연출
3.25초 → 진입이라 대개 그 안에 든다. 거부돼도 레이아웃이 이미 전면이라 보이는 건
거의 같고, 하단 `⛶` 버튼이나 **영상 더블클릭**으로 다시 켤 수 있다(해제는 `Esc`).

전체 화면 대상은 `<video>` 가 아니라 **오버레이를 감싼 스테이지 요소**라서 전체
화면에서도 상단/하단 바가 남는다. 관제 화면의 시뮬 최대화·미니 패널에서도 된다.

시뮬 영상이 나오는 동안에는 웹의 `REC ●` 와 `CAM 01 · 3RD PERSON` 오버레이를
숨긴다 — Unity 캠코더 HUD 에 이미 `REC` / `TELLO CAM-01` 이 있어 겹쳐 보였다.

### 창 타이틀바 잘라내기

창 캡처는 `tello_simulator [ㅡ][ㅁ][X]` 타이틀바까지 같이 찍는다. **프레임에 박혀
오는 거라 웹에서 전체 화면을 해도 안 없어진다.**

- **근본 해결(권장)** — Unity 를 테두리 없이 띄운다. 리빌드 없이 지금 당장은
  `tello_simulator.exe -popupwindow`, 영구적으로는 `WindowMode.cs`
  (`README-integration.md` §2). 잘라내기 없이 원본 해상도 그대로 깨끗해진다.
- **차선** — 영상 위쪽을 잘라낸다. 시뮬 화면 우하단 `⊟ N%` 의 `−`/`+` 로 조절하고
  값은 `localStorage` 에 남는다. 기본값은 "창 내용이 16:9" 라고 보고 자동 추정한
  값이라, 16:9 가 아니면 0% 로 두고 직접 맞추면 된다.
  CSS `object-view-box` 를 쓰므로 Chrome/Edge 104+ 에서만 동작한다(Firefox 는 그냥
  안 잘릴 뿐 깨지지 않는다).

> 화면 공유 방식의 한계: 켤 때마다 창을 골라야 하고, Unity 창을 최소화하면 프레임이
> 멈추고, 드론 카메라가 아니라 **Unity 창 전체**가 찍히며, 무엇보다 **서버가 프레임을
> 볼 수 없다**. 사람 탐지(2D detection)를 붙이려면 Unity 가 카메라 프레임을 직접
> 송출(예: RenderTexture → JPEG → MJPEG/TCP)하도록 바꿔야 한다.

## 사람 탐지 통보

순찰 경로 계획 · 360도 스캔 · 2D 사람 탐지 · 탐지 판단은 **전부 LLM 에이전트가
한다.** 웹은 "찾았다"는 통보를 받아 작전 화면에 그리기만 한다.

- 카메라 위 **바운딩 박스 + 라벨**(`생존자 N`, 신뢰도) 과 상단 **경고 배너** —
  둘 다 **2초 깜빡이고 사라진다**(`ALERT_MS`). 화면을 계속 가리지 않는다.
- 토스트 + 우측 **발견 목록**(번호 · 라벨 · 방 · 시각, 최신순)은 남는다.
- 통보 순간 시뮬 영상에서 **한 프레임을 떠 박스를 그려 저장**한다 →
  순찰 보고서의 생존자 사진. 화면 공유가 꺼져 있으면 `NO FRAME` 으로 뜬다.

연동 입구는 이거 하나다:

```js
window.__patrolDetect({ label: '생존자 1', room: '현우의 도청 장비실',
                        conf: 94.2, box: { l: 21, t: 33, w: 16, h: 40 },
                        photo: null })
```

전부 생략 가능하다 — `label` 은 `생존자 N`, `room` 은 순찰 대상 순서대로,
`box` 는 미리 잡아 둔 자리에서 순번대로, `photo` 는 프레임 자동 캡처로 채운다.
`box` 의 `l/t/w/h` 는 **프레임 대비 %** 다. YOLO 2D 탐지가 붙으면 실제 bbox 를
%로 바꿔 넘기면 화면 박스와 보고서 사진 둘 다 그 자리에 그려진다. 생존자/피해자
구분은 `label` 로 넘겨받으면 된다.

> 작전 화면 하단의 **「임시 · 생존자 발견」 / 「탐지 초기화」 버튼**은 LLM 연동
> 전에 화면을 확인하려고 둔 것이다. 그 버튼도 결국 `window.__patrolDetect()` 를
> 부를 뿐이라, **연동되면 버튼 두 개만 지우면 된다**(표시 로직은 그대로 쓴다).
> 탐지 목록은 새 순찰을 시작할 때(`startMission`) 비워진다.

## 주의

- `web_server.py` 의 `ENV_KW` 는 학습 당시 설정이다. 바꾸면 정책 성능이 무너진다.
  특히 `clearance=0.12` 는 반드시 명시(기본 0.235로 env 를 만들면 `geo_graph_cache`
  가 덮여서 다음 실행이 캐시를 1분간 재생성한다).
- `support.js` 는 생성된 런타임이라 직접 수정하지 말 것.
- 환경 객체는 재진입 불가라 서버가 Lock 으로 요청을 직렬화한다. 다구간 계획은
  구간 수만큼 순차 요청이 나가므로 방이 많으면 그만큼 시간이 걸린다.
- 아직 구현되지 않은 단계: 순찰 구역 도착 시 **360° 스캔 / 사람 탐지 판단**
  (LLM·YOLO 쪽 몫). 「순찰 완료」는 현재 운용자가 누르는 버튼이다.

## 순찰 보고서

「순찰 완료」 화면의 **「순찰 보고서 보기」** 로 들어간다. 새 자료를 받지 않고
**브리핑 때 확정된 순찰 계획 + 탐지 통보 + 작전 시작·완료 시각**만으로 만든다.

- 좌: 발견 수 · 순찰 개요(범위/층/구역/거리/층 이동/엔진/시각/소요/복귀) ·
  **작전 타임라인**(실제로 찍힌 시각만 — 시작, 각 탐지, 완료)
- 중: **구역별 탐색 결과** — 순찰 대상마다 `생존자 N명` / `이상 없음`
- 우: **발견된 생존자 카드** — 탐지 순간 캡처 사진 + 라벨 · 방 · 시각 · 신뢰도

방별 도착 시각처럼 웹이 모르는 값은 만들어 넣지 않는다. 필요해지면 진행 로그
입구(`window.__patrolLog`)를 새로 열어 LLM 이 보내는 쪽이 맞다.
