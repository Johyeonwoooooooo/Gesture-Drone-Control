# 드론 자율비행 RL — 수동 커리큘럼(v1) → 측지 보상 + 자동 커리큘럼(v2)

> Matterport 3D 스캔 집(22개 방·3층) 점군 위에서, 드론이 시작점→도착점으로 스스로 나는 정책을 SAC로 학습.
> 정책이 보는 것은 **센서뿐**(목표 방향·거리 + 14방향 거리센서 + 직전 행동) — 지도 없음.

---

## 1. 한 줄 요약

**"사람이 난이도를 5단계로 쪼개 떠먹여주던 학습(v1)"을 "보상이 길을 알고, 환경이 스스로 난이도를 올리는 학습(v2)"으로 재설계** — 그 결과 수동 단계 없이 계단(층 넘기) 포함 집 전체를 한 번의 학습으로 커버.

---

## 2. Before — v1: 수동 커리큘럼 (2026-06-27 ~ 07-13)

같은 방 2m → 문턱 넘기 → 옆방 → 같은 층 8m → … 처럼 **사람이 난이도 단계를 설계**하고, 단계마다 학습→평가→진급 판정을 반복.

| 단계 | 과제 | 결과 (결정론 성공률) |
|---|---|---|
| 1 | 같은 방, ≤4m | 0.75 ✅ |
| 2a | 문턱 넘기 (문 앞↔문 뒤) | 0.78 ✅ |
| 2b | 문 하나로 연결된 옆방 | 0.68 ✅ |
| 2c | 같은 층 아무 두 방, ≤8m | **0.47 정체** → 문 경유 보상 추가 후 0.63 🔶 |
| 2d | 같은 층 무제한 | (미진행) |
| 3 | 전 층 (계단 포함) | **성공률 0 고정** ⛔ |

### v1이 막힌 3가지 근본 원인

1. **보상이 길을 모름** — "목표까지 직선거리가 줄면 +보상"인데, 목표가 옆방이면 최단 직선은 벽을 통과함. 보상이 드론을 벽으로 밀어붙이는 local optimum → 2c가 0.47에서 정체. (문 경유 보상을 수작업으로 붙여 0.63까지 올렸지만, 방그래프 BFS·문 통과 판정 등 수제 로직이 계속 불어남)
2. **수동 커리큘럼의 비용** — 단계 설계, 단계별 스크립트, 진급 기준, 이어받기 체인… 전부 사람이 관리. 단계 사이 이어받기에서 정책 파괴 사고도 발생.
3. **계단은 원리적으로 불가** — 좁은 계단은 드론 여유반경(0.235m)으로는 물리적으로 통과 불가 + 성공 경험이 0이라 학습 신호 자체가 없음.

## 3. After — v2: 측지 보상 + 자동 커리큘럼 (2026-07-13 재설계)

### 핵심 아이디어 ① 측지거리 potential-based reward shaping

- 집을 0.3m 격자(유효 셀 3.1만 개)로 깔고, 목표까지의 **측지거리 φ**(벽을 돌아가는 실제 최단거리)를 Dijkstra로 계산
- 보상 = (φ이전 − φ현재) × 5 → **보상 기울기가 항상 문·계단을 지나는 실제 경로를 가리킴**
- 벽-유인 local optimum이 원천 소멸. v1의 문 BFS·통과 판정 등 수제 로직 전부 삭제
- potential-based shaping은 **최적 정책을 바꾸지 않는다는 이론 보장** 있음 (Ng et al. 1999)

### 핵심 아이디어 ② 성공률 적응형 자동 커리큘럼

- 목표를 정하면 Dijkstra 필드가 생기므로, **시작점을 원하는 측지거리 밴드 [d_max−3, d_max]에서 공짜로 샘플** 가능
- 최근 30 에피소드 성공률 > 60% → d_max +0.25m / < 30% → −0.25m
- 수동 5단계가 **온도조절기 하나로 대체** — 2m에서 시작해 최대 ~45m(집 전체 측지 지름)까지 스스로 올라감
- 참고: 집 자체는 17.8×13.0×8.8m라 직선 최장은 21.7m뿐. 45m는 문·계단을 거치는 실제 비행거리
  (최극단 쌍: 직선 11.8m(꼭대기층↔바닥층, 천장 관통 기준)인데 실제 경로는 45.3m — 우회비율 3.8배.
  직선거리 보상(v1)이 왜 실패하고 측지 보상(v2)이 왜 필요한지를 그대로 보여주는 수치)
- 에피소드의 20%는 전 난이도 균일 샘플(짧은 과제 망각 방지, 적응 통계에서는 제외)

### 핵심 아이디어 ③ Asymmetric actor-critic — 특권 정보의 경계

- 관측을 Dict로 분리: `sensor`(21차원) + `priv`(측지거리 φ + 측지 하강방향, 4차원)
- **actor는 sensor만, critic은 sensor+priv** — 코드 구조(추출기 주입)로 강제 (Pinto et al. 2017)
- 진짜 측지거리를 아는 critic은 가치 추정이 정확 → 저분산·안정 학습
- "지도 어디서 났나?" → **시뮬레이터 특권 정보이고, 보상·critic까지만 주고 actor에서 끊었다.** priv를 0으로 강제해도 행동이 동일함을 테스트로 증명 → 배포 시 정책은 센서만으로 비행

### 핵심 아이디어 ④ 계단 물리 보정

- 계단 통과 경로를 grid A*로 한 번 계산해두고, **그 경로 주변 0.9m에서만** 여유반경 0.235→0.12m 완화
- 측지 격자도 같은 규칙 → 필드가 계단을 타고 층을 넘음 (검증: 꼭대기층 목표 → 바닥층 100% 도달 가능)
- 층 넘기가 특별 취급 없이 커리큘럼에 자연 포함됨

### 학습 인프라

- 병렬 6개 환경(SubprocVecEnv)으로 CPU 병목(KDTree 충돌검사) 우회
- **시간 예산 정지**: 스텝 수가 아니라 시간(`--hours`, 기본 22h)으로 종료 — fps 변동과 무관하게 예산 준수
- 안전장치: 발산 자동중단 가드(ent_coef 감시), 100k마다 체크포인트, 평가 최고 모델 자동 저장, 원자적 저장

| | v1 (수동 커리큘럼) | v2 (측지 + 자동) |
|---|---|---|
| 난이도 설계 | 사람이 5단계 수동 설계·진급 판정 | 성공률 적응형 자동 (온도조절기) |

## 5. 학습 곡선 읽는 법 (중요)

- `rollout/success_rate`가 **높→낮→회복 톱니를 그리는 게 정상** — 성공률이 오르면 커리큘럼이 난이도를 올려 다시 떨어뜨리는 온도조절기 동작
- 진짜 진행 지표는 ① `rollout/d_max`(난이도)의 우상향, ② `eval/success_rate`(전 난이도 균일 평가 = 진짜 실력)의 상승

## 6. 실행 · 평가 명령어

```bash
conda activate tello
cd playground/reinforce_learning

# 학습 (시간 예산, 돌리고 자면 됨)
python train_geo.py --hours 16

# 중단해도 이어받기 가능 (버퍼 자동 로드, 이음새 없음)
python train_geo.py --init-from model_geo --hours 8

# 학습 곡선
tensorboard --logdir runs        # rollout/d_max, eval/success_rate 확인

# 전 층 태스크 배치 평가 (같은 층 / 층 넘기 성공률 분리 리포트)
python evaluate_geo.py --random 60

# 3D 시연: 층이 다른 두 점 찍어 계단 넘는 비행 보기
python evaluate_geo.py --pick

# 특권 정보 경계 증명 (priv=0 강제해도 성적 동일)
python evaluate_geo.py --random 20 --prove-boundary
```

생성 파일: `model_geo.zip`(최종) / `model_geo_best.zip`(평가 최고 — 시연은 보통 이걸로) / `model_geo_replay.pkl`(이어받기용)

## 8. 다음 단계 (일반화 로드맵)

1. **절차적 집 생성** — 무작위 방·문·계단으로 집 200채를 합성해 학습, demo_house는 테스트셋으로. "이 집을 외운 게 아니라 나는 법을 배웠다"를 제로샷 평가로 증명
2. **Teacher-student 증류** — 측지 필드를 관측으로 받는 teacher를 빠르게 학습 → DAgger로 센서-only(+기억) student에 증류. 특권 정보 경계가 더 선명해짐
3. **온라인 믿음 지도** — 에이전트가 자기 레이캐스트로 점유격자를 누적하고 그 위에서 Dijkstra(free-space assumption) → 처음 보는 건물에서도 동작하는 배포형
